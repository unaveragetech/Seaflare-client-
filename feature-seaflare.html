Feature — Bundled Seaflare

Combat and market, in one client.

Seaflare Market bundles a rebranded, GPL-compliant build of LiquidBounce so combat modules and market tooling share one install and one interface — not two mods fighting for the same inputs.

One ClickGUI

Market tools and Seaflare's combat modules live in the same interface — no alt-tabbing between two mods.

Reflection bridge

Talks to Seaflare by resolving its classes at runtime — the market side keeps working even if Seaflare is unavailable.

Documented modifications

Every change from upstream LiquidBounce is cosmetic and listed in full — nothing is silently altered.

How it works

Cosmetic changes only, and reflection instead of a hard dependency.

Bundling someone else's GPL-licensed client responsibly means being precise about what changed — and building the connection to it so it can never take the rest of the client down with it.

What actually changed from upstream

The bundled build is Seaflare — a rebrand of LiquidBounce. Every modification is cosmetic: the displayed name, the logo and wordmark artwork, the title-screen background, and the menu's accent colour. No feature was added, removed, or reimplemented. Every button still calls exactly the function it called upstream — the shader toggle still toggles the shader, the website button still opens the same URL. Package names, translation keys, and every asset identifier that code actually resolves by name were deliberately left untouched, because renaming those would be a real code change disguised as a cosmetic one.

  • GPL-3.0 §5(a) compliant — every change is listed in the shipped notice file, not just claimed.
  • Authorship credit unchanged — Seaflare's original author credit is left exactly as upstream.

Why reflection, not a compiled dependency

Seaflare Market never compiles directly against Seaflare's classes — it resolves them by name at runtime instead. That single decision is what stops a future Seaflare rebuild from being able to take the rest of the client down with it: if a class or method it looks for isn't there, the bridge reports itself unavailable and every unrelated system — the auction house, the RTP mapper, the HUD editor — keeps running exactly as before.

One HUD, one keybind system

Seaflare's HUD elements and this project's own HUD components are edited through the same draggable editor, and Seaflare's modules are bound through the same middle-click watcher documented on the HUD & Module Browser page. There's no second settings system to learn for the combat side of the client.
