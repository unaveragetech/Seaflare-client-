Overview

Four systems, one goal: spend less time managing the market, more time playing.

Everything ships client-side. Every automated action goes through the same humanized input path as a real mouse and keyboard — no packet forging, no flat cadence.

Market automation

Sell-lot assembly, listing sync, arbitrage scans, and order queues that watch the auction house so you don't have to.

RTP intelligence

Round-robin region sampling, duplicate-landing detection, and criteria-driven searches for a base, a mine, or a build spot.

HUD & modules

A draggable, resizable HUD editor and a full module browser — every element and module has real, reachable settings.

Safety net

Panic Mode, Auto Log and Auto Relog watch health, damage bursts, and nearby players so a bad fight doesn't cost a session.

Feature set

Every panel opens into real, working settings.

Six groups cover the whole client. Open a panel for the short version, or visit a feature page for the full breakdown — no code, just what each piece actually does.

  • Live listings sync — your own AH listings tracked and reconciled automatically.

Spotlight — RTP Mapper

Turn a random-teleport gamble into a search.

Instead of spamming /rtp and hoping, the mapper samples every enabled region on rotation, plots every landing on a live map, and can hunt for a spot matching your own criteria — then stop the moment it finds one.

  • Region-targeted or plain /rtp, mixed at a ratio you control.
  • Cluster detection rotates away from ground already mapped.
  • The overlay survives a teleport — the game replaces the screen mid-sample, the mapper puts it back.

Spotlight — Auction House

The market, watched continuously.

Listing a lot is a verified sequence, not a hopeful click. Every step confirms the item actually moved before the next one fires — the same discipline applied to scanning the market for underpriced listings.

  • Sell-lot assembly is verified, not assumed — every click is checked against real inventory state.
  • Standing sell/buy rules that keep retrying and reporting status.
  • History-aware pricing flags listings worth acting on fast.

Where the work is going

Development is currently focused entirely on DonutSMP.

Region ids, cooldown pacing, the AH click flow, and every default in this client are tuned against one real server — not a generic guess at how "a survival SMP" might behave.

  • Region set matches DonutSMP's real proxy backends — sampling isn't guessed geography, it's the server's actual routing.
  • AH automation follows DonutSMP's exact command flow, including the quirks a generic client would get wrong.
  • Cooldown timing is learned from this server specifically, with automatic backoff when it disagrees.
  • Depth over breadth, for now — one server done right, before spreading thin across many.
