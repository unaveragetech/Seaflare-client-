Feature — HUD & Module Browser

Every panel opens into real settings.

A draggable HUD editor and a searchable module browser that share one rule: if it's on screen, it has a working settings panel behind it — never a blank box.

Drag, resize, snap

Move any HUD element with the mouse, resize it, and snap it to a grid — with live preview, not a coordinates form.

Middle-click binding

Middle-click a module, press a key or mouse button, done — the same gesture modern clients use.

Searchable browser

Category tabs, live status lines, and a search box that filters as you type across every module.

How it works

Settings that actually fit what they're configuring.

A settings window used to be a fixed 240×230 box regardless of whether the module had two settings or thirteen. It now sizes to the module, scrolls when it needs to, and clips its own content instead of painting over its header.

The keybind watcher

Middle-click a module row (or the key row inside its settings window) and it switches to press a key — the next key or mouse button becomes the bind. A modifier key alone doesn't end the watch, since almost every real bind is pressed on the way through Shift or Ctrl. Delete or Backspace clears the bind instead; Escape or a left-click cancels. This replaced an older scheme where hovering a row and pressing any key rebound it — which meant a stray keystroke while the mouse sat over a module silently changed its bind.

No such thing as an empty settings panel

HUD components like the watermark or the coordinate readout used to declare no tunables at all — opening their settings window showed an empty box that looked broken. Every component now gets an enable switch at the top of its window regardless of whether it has anything else to configure, with a note saying so when it doesn't. The same enable switch is also reachable directly from the HUD editor's sidebar list, so turning an element off never requires opening its window at all.

Typing actually works

Text fields accept every printable character plus full clipboard paste. An earlier version whitelisted a narrow set of characters that didn't include a period — which meant a server address or a webhook URL couldn't be typed into a text setting at all, with no error, the keystroke just didn't appear.
